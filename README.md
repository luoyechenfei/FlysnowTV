# 飞雪TV（FlysnowTV）· Android TV 版

主流深蓝主调、玻璃拟态海报墙风格的电视直播播放器。原生 Android（Kotlin + Media3/ExoPlayer），可直接装到安卓电视盒子自用测试。

> 当前版本 **1.9.1（versionCode 12）**，包名 `com.iptv.tvplayer`，minSdk 21 / targetSdk 34。
> 本仓库只包含源码：编译产物与 release 签名密钥按 `.gitignore` 排除，请按「重新打包」一节自行构建 `FlysnowTV.apk`。
> 直接装现成签名包：[Releases 发布页](https://github.com/luoyechenfei/FlysnowTV/releases)（最新为 **v1.9.1**）。

### 检测更新怎么用

1. 设置中心（右上角「设置」按钮、长按 `MENU` 3 秒，或底部信息栏里的「设置」按钮）→ 关于 → **检测更新**，App 请求 `https://api.github.com/repos/luoyechenfei/FlysnowTV/releases/latest`。
2. 把返回的 `tag_name`（如 `v1.9.1`）与本机 `versionName` 按数字段比较（`1.9.1 > 1.9`、`1.10 > 1.9`，不会按字符串误判）。
3. 有新版本 → 弹窗显示版本名、包大小与 Release 说明摘要，点「一键在线更新」下载 `FlysnowTV.apk` 并调起安装界面；盒子需开启「允许安装未知来源应用」。
4. 已是最新版本 → 提示当前版本与 latest 版本，仍可「重新下载安装」验证链路；也可打开「版本发布页」查看全部 Release。

## 历史版本 · 1.3 新增：订阅链接一键导入 + 盒子自适应 + 日志 + 白色雪花 LOGO

### ① 只要一个 URL，一键导入

不需要复制列表内容、不用填请求方式 / 字段映射。支持 `.m3u` / `.m3u8` / `.txt` / JSON / 任意接口地址，例如：

```
https://www.example.com/iptv6.m3u
https://www.example.com/iptv6.txt
```

三个入口，都是「粘贴链接 → 一键导入」：

| 入口 | 位置 |
| --- | --- |
| 电视端 | 设置中心最上方「**粘贴链接，一键导入**」；或「从剪贴板一键导入」 |
| 手机端 | 设置 → 打开二维码 → 手机网页第一张卡片「**一键导入订阅链接**」 |
| adb / 深链 | `am start -a android.intent.action.VIEW -d "https://x/all.m3u"`；任意地址用 `flysnow://import?url=<URL 编码>` |

- 一行一个可批量（最多 20 条），自动识别 URL、支持 `名称,URL`、裸域名自动补 `https://`
- 可填**可选请求头**（Referer / User-Agent），第三方接口不用再展开整张高级表单
- 导入时**真实拉取并校验**，只有能解析出频道的才保存；失败逐条给出原因；勾「替换」且全部失败时保留原配置
- `.txt` 支持 diyp 的 `分组名,#genre#` 分组；`.m3u` 头部 `x-tvg-url` 会自动填成 XMLTV 节目单地址
- 导入成功后返回频道墙即加载，**全部频道都来自你自己的订阅**（应用不内置任何频道）

### ①-附 订阅地址可管理（编辑 / 停用 / 排序 / 校验 / 删除）

所有导入的订阅统一出现在设置中心「第三方接口」下方的列表里，每条都可点开管理：

- **编辑**：改地址、请求方式、请求头、Token、字段映射，保存即覆盖原配置
- **启用 / 停用**：临时屏蔽某个订阅而不删除；停用的订阅不参与合并、也不应用其请求头（拉取时实时统计「已启用 N 个」）
- **上移 / 下移**：调整多源合并的优先级（同名 / 同 tvg-id 频道只显示一张卡片，**排在前面的订阅作主线路**，其余订阅的同名地址自动变成备用源）
- **重新校验**：单独拉一次该订阅，显示解析到的频道数与失败原因
- **删除**：从电视端移除

手机扫码配置页的「已添加的订阅」同样支持编辑、启用/停用、上下移与删除。

### ①-附-2 订阅备份（导出 / 导入）

所有订阅（地址、请求方式、请求头、Token、字段映射、启用状态、排序）可以整体导出成一个 JSON 文件，方便换机、分享或留底；也可以从备份恢复。

- **导出**：设置中心「第三方接口」下的「**导出订阅备份**」会生成 `FlysnowTV_sources_时间戳.json` 到 App 专属 Download 目录，并提示 `adb pull` 取回路径；手机扫码配置页也有「**下载订阅备份**」按钮直接下载。
- **导入**：电视端「**导入订阅备份**」会拉起系统文档选择器（U 盘 / 下载目录 / 网络存储都可），选中 `.json` 后弹出**合并导入 / 替换全部**确认框；手机配置页则粘贴备份 JSON 内容，勾选「替换全部」即整体覆盖，否则按地址合并（新增不重复项、不动现有其它订阅）。
- 备份文件就是一份带 `app/type/version/sources` 字段的 JSON，人眼可读、可手改；损坏项会自动跳过，只恢复能解析的频道源。

### ② 老盒子 / 新盒子自动适配（HLS 与解码）

`DeviceProfile` 按系统 API、WebView Chrome 版本、内存把设备分成三档，只影响**起播与解码策略**（全部频道都是自带订阅直连播放）：

| 设备 | 自动采用的方案 |
| --- | --- |
| 新盒子（WebView ≥ 70、API ≥ 24） | HLS 免分片快速起播，短缓冲 |
| 老盒子 / 内存小 | 标准 HLS 路径 + 解码器软解回退 |
| 无 WebView 组件 | 只依赖直连源播放（不影响本应用） |

- 内置解码连续失败 2 次，自动尝试盒子上已装的 VLC / MX / 系统播放器（可关）
- 启动时自动为 API ≤ 22 老盒子启用 **TLSv1.2**（「装得上、一个频道都播不了」的最常见原因），并恢复**软解回退**

### ③ 日志生成 / 排障

设置 →「播放诊断」：查看设备信息、TLS 状态、设备自动分级、每次接口拉取结果、起播与播放错误码；「**生成日志文件**」导出 `FlysnowTV_log_时间戳.txt` 到 App 专属 Download 目录，可 `adb pull` 取回。运行日志 `files/diag.log`、崩溃日志 `files/crash.log`。

### ④ LOGO

应用图标、TV 桌面横幅、界面顶部品牌标记统一改为**纯白色六角雪花**，取消「飞雪TV」文字（应用名称仍为飞雪TV）。生成脚本 `scripts/gen_assets.py` 可复现。

## 历史版本 · 1.2 新增：盒子性能修复 + 多线路 / 时间轴 / 回看

### 为什么盒子上会「卡在图标界面」、画面出来后又很卡

模拟器能播、盒子卡住，主要不是源的问题，而是**低端盒子只有一路硬件视频解码器**：

| 旧版问题 | 1.2 修复 |
| --- | --- |
| 每张海报卡片都 inflate 一个 `TextureView`（一屏几十个），启动首帧被 SurfaceFlinger 拖死 | 卡片只留空 `previewHost`，**全局只有一个**预览 `PlayerView`，聚焦时动态挂载 |
| 返回频道墙后全屏播放器继续解码，同时卡片预览又拉一路流 → **双路硬解直接卡死** | 回墙面立即 `pause()` 并把全屏 `SurfaceView` 置 `GONE`，系统销毁 surface 释放解码器；设置里可自愿开启后台续播 |
| 预览默认开启、0.7 秒就起播，遥控器连按会不断创建/销毁 HLS 加载器 | 预览**默认关闭**，延迟 1.2 秒，播放器懒创建，连续失败 3 次自动彻底释放 |
| 标准模式要预取 **50 秒**缓冲才起播 | 缓冲降到 8~15 秒、起播阈值 0.5~1 秒；**默认改为加速引擎** |
| HLS 起播需多拉几个分片，失败重试久 | `HlsMediaSource` 免分片预加载 + 2 秒时间戳初始化 + 减少分片重试；连接/读超时 8/10 秒快速失败 |
| 收藏状态每次绑定都重新解析 JSONArray（上千频道时 O(N×M)） | 进程内静态缓存；列表内容没变就不 `notifyDataSetChanged`；焦点动画去掉 elevation；台标去掉 crossfade |
| 后台每分钟新建多个线程拉 EPG | 固定 2 线程池 + EPG 加载去重 + 5 分钟检查一次；崩溃日志写入 `files/crash.log` |

> 如果盒子仍然卡：设置 →「性能 / 盒子流畅度」保持**预览关闭 + 后台续播关闭**，画质选 **720p 或省流**，并优先使用较稳定的 m3u8 直连源。

### 本版新增功能

| 功能 | 说明 |
| --- | --- |
| **多线路自动切换 / 备用源** | 多个订阅里同名 / 同 `tvg-id` 的频道**只留一张卡片**：排在前面的订阅作主线路，其余订阅的地址自动成为备用源（缓存里用 `#FX-ALT:`）；播放失败自动切下一条并记住可用线路；播放态 `← →` 快速切线路，**长按 `OK` 打开「换源」菜单**按来源挑选；设置里可关自动切换 |

## 功能总览

- **海报墙首页**：按屏幕宽度自动分列（1080p 约 5 列），台标 + 频道名 + 收藏星标，聚焦放大 7% 并加发光描边
- **全部自定义导入**：应用不内置任何频道，所有频道都来自你添加的订阅源（m3u / m3u8 / txt / JSON 接口 / 单个流地址）
- **多播放源 / 第三方接口**：m3u、JSON 接口、单个流地址可同时添加；**多个订阅里的同名频道只显示一张卡片**，排在前面的订阅作主线路，其余订阅的地址自动成为备用源
- **分组筛选**：`group-title` / JSON 分组 + 收藏 / 最近观看虚拟分组；不同源里只是写法不同的分组（`卫视` / `卫视频道`）合并成一个筛选入口
- **全屏播放**：信息浮层 5 秒隐藏；BACK 回墙面时暂停并释放视频解码器（设置里可开启后台续播）
- **多线路 / 备用源**：播放态 `← →` 快速切线路，**长按 `OK` 打开「换源」菜单**按来源挑选；失败自动切换并记忆可用线路
- **EPG 时间轴与预约**：6 小时网格视图、节目预约、开播前 1 分钟提醒、OK 一键跳台
- **回看 / 时移**：catchup 模板 + 快捷时移档位 + 按 EPG 节目回看（需源支持）
- **换台**：CH+/CH-、播放态上下键、数字键选台（屏幕实时显示台号与候选频道，OK 立即跳转 / DEL 退格 / BACK 取消 / 2.5 秒自动确认，最多 4 位）
- **画质分辨率**：自动 / 最高码率 / 1080p / 720p / 480p / 省流，播放信息栏显示实际解码分辨率
- **内置加速 + 第三方播放器**：低延迟缓冲 + 直播追帧；也可交给 VLC / MX Player / Kodi / 系统播放器
- **台标 LOGO 获取**：接口 `tvg-logo`、自定义地址模板两种来源
- **界面**：柔光拟态半透明信息卡 / 底部频道信息栏（台标、线路、节目进度、分辨率、播放控制、内核、画质、设置）+ 扁平单色矢量图标
- **换台信息卡**：频道号、名称、分组、当前节目、播放方式与实际分辨率，8 秒自动收起
- **关于菜单**：版本号、版权与授权、项目主页、检测更新与一键在线更新、日志上报反馈（扫码 / 微信 / QQ 分享）
- **雪花品牌**：1.9 起为深蓝底扁平单色雪花矢量图标（信息栏 / 设置 / 按钮统一），不含文字；1.3 的纯白雪花 LOGO 为早期样式。应用名称仍为「飞雪TV」

## 关于播放源

本应用**不内置、不分发任何频道或直播流地址**。所有频道都来自使用者自行添加的订阅源（聚合 m3u / txt、第三方 JSON 接口、单个流地址等）。点卡片即用 ExoPlayer 直连播放，不再跳转任何官方网页。

- 请只导入你有权使用的源；自用测试请保持私用，不要分发、不要公开提供流地址
- 频道按 m3u 里的 `group-title` 自动分组；没有分组的归入「其他」
- 同一频道在多个源里出现时自动合并成多线路，播放失败自动切换

### 多个订阅怎么合并（1.5）

同时添加多个订阅时，**不会每个订阅各铺一遍频道墙**：

| 规则 | 说明 |
| --- | --- |
| 判定同一个频道 | 先看 `tvg-id`，再看归一化频道名（忽略空格、`-`、大小写、`高清/超清/标清/HD`），最后按 CCTV 台号兜底（`CCTV-1` ≈ `CCTV1` ≈ `CCTV-1 综合`；带 `欧洲/美洲/4K` 等区分词的不合并） |
| 谁当主线路 | **设置里排在最前面的启用订阅**。用「上移 / 下移」调整优先级，主线路始终来自排第一的那个源 |
| 其他源呢 | 同名的地址按顺序变成备用线路，界面上仍是同一张卡片；节目单、分组筛选、收藏、最近观看也都只出现一次 |
| 怎么用备用源 | 播放态 `← →` 快速切下一条；**长按 `OK` 打开「换源」菜单**，列表里带来源名（域名 / 文件名）与地址，选一个立即切过去；某条线路播不出来会自动跳到下一条，成功的那条会被记住 |
| 分组名去重 | `卫视` 与 `卫视频道`、`央视` 与 `央视 ` 这类只差写法的分组归成一个筛选入口，避免筛选条出现一串重复项 |

> 只想要某一个订阅独播？把它「上移」到第一位即可；暂时不需要某个订阅就「停用」，它既不参与合并、也不会占用主线路。

## 手机扫码配置（推荐）

设置中心第一项「**打开二维码 / 启动配置页**」→ 电视显示二维码、局域网地址与 4 位 PIN → 手机（同一 WiFi）用相机 / 微信扫码打开配置页。

- TV 端内置轻量 HTTP 服务，端口 **8899**，只在打开二维码页时运行，退出即关闭
- 手机网页第一张卡片就是「**一键导入订阅链接**」：粘贴一条或多条 `.m3u` / `.txt` 地址、可选请求头，一键校验并保存到电视
- 也可以：增删接口（含 GET/POST、请求头、请求体、Token 接口与路径、刷新周期、字段映射）、粘贴整段 m3u 文本、**下载 / 粘贴导入订阅备份**、修改画质 / 播放器 / 台标 / 预览开关 / 后台续播 / 线路自动切换 / XMLTV 地址 / Token 周期、立即刷新 Token 与节目单
- 所有写操作校验 PIN；数据只保存在这台盒子的 App 内部，不上传任何服务器
- 接口 / XMLTV 地址变更会递增 `Prefs.version`，回到频道墙自动重载；画质、引擎等只影响播放的设置即时生效，不会无谓重新拉接口

不想扫码也可以在手机浏览器直接输入电视屏幕上显示的地址（`http://盒子IP:8899/?pin=xxxx`）。

## 第三方接口：GET / POST / Token

「添加接口」字段：

| 字段 | 说明 |
| --- | --- |
| 接口地址 | m3u / m3u8 / JSON 接口 / 单个流地址，支持 `{token}` 占位 |
| 请求方式 | `GET` 或 `POST`（填写其它值自动回退 GET） |
| POST 请求体 | 支持 `{token}`；以 `{` 开头自动用 `application/json`，否则表单格式 |
| 自定义请求头 | 每行 `Key: Value`，值里可写 `{token}`；接口请求与视频播放都会带上 |
| JSON 字段映射 | `name=title,url=playUrl,logo=icon,group=category,tvgId=channelId,root=data` |
| Token 接口地址 | 留空表示不需要 Token；GET/POST 跟随该源的请求方式与请求体 |
| Token 字段路径 | 如 `data.token`、`result.0.access_token`；留空 = 整段响应当 Token |
| Token 刷新周期 | 分钟，0 = 跟随全局设置 |

**自动识别的返回格式**：`#EXTM3U` 列表、JSON 顶层数组、任意层级嵌套数组（`data.list` / `rows` / `result`）、JSON 字典 `{"频道名":"url"}`、纯文本多地址、单个流地址。相对地址按接口地址补全，GBK 编码自动兜底，gzip 响应自动解压。

**adb 一键导入**（最省事，不需要扫码）：

```bash
adb connect 192.168.1.x:5555

# 标准 .m3u / .txt 聚合订阅地址
adb shell am start -a android.intent.action.VIEW -d "https://www.example.com/iptv6.m3u"

# 没有扩展名的任意接口地址（url 参数需 URL 编码）
adb shell am start -a android.intent.action.VIEW -d "flysnow://import?url=https%3A%2F%2Fx.com%2Fapi%2Flist"

# 需要请求头的第三方接口
adb shell am start -a android.intent.action.VIEW -d "https://x.com/api/list" \
  --es headers "Referer: https://x.com/"
```

**adb 高级接口配置**（POST / Token / 字段映射）：

```bash
adb connect 192.168.1.x:5555

# 普通 GET 接口
adb shell am start -n com.iptv.tvplayer/.MainActivity -d "http://192.168.1.10/api/channels"

# POST + 请求头 + 字段映射 + Token
adb shell am start -n com.iptv.tvplayer/.MainActivity \
  -d "https://api.example.com/live/list" \
  --es method "POST" \
  --es body "page=1&token={token}" \
  --es headers "Authorization: Bearer {token}" \
  --es fields "name=title,url=playUrl,group=category" \
  --es tokenUrl "https://api.example.com/token" \
  --es tokenPath "data.token" \
  --es refresh "15"
```

## XMLTV 节目单

在「设置 → XMLTV 节目单」填地址（也支持手机扫码页填写），支持 `.xml` 与 `.xml.gz`。解析标准 `<channel><display-name>` 与 `<programme start/stop/channel>`，含时区偏移（`20261108013000 +0800`）。

- 频道匹配顺序：`tvg-id` 精确 → `tvg-id` 前缀（如 `cctv1.cn`）→ `display-name` 精确 → CCTV 频道号宽松匹配（`CCTV-1` / `cctv01` / `央视一套` 互通，5+ 单独区分）→ 中文台名包含
- 播放态按 `OK` 呼出左侧节目单：每行显示当前节目与后续节目，底部是选中频道的节目时间轴与进度
- 播放态按 `GUIDE` / `INFO` / 电视键打开**时间轴网格**：一次看 8 个频道 × 6 小时，节目块按真实时长铺开，红色竖线标当前时间。`↑↓` 选频道、`←→` 选节目、`OK` 预约或取消（金色）、播放键立即跳到该频道
- **预约提醒**：应用在前台时每分钟检查，开播前 1 分钟弹出顶部提醒卡，按 `OK` 直接跳台；已触发的预约自动从列表移除。设置里可查看 / 清空
- 换台信息卡显示当前节目；缓存写入 App 内部，断网仍可看当天节目
- 定时刷新：前台每 5 分钟检查一次，超过设定间隔自动重拉；设置里可「立即刷新」

`m3u` 里的 `tvg-id`、JSON 接口里的 `tvgId / channelId / id` 都会作为匹配键，同时也是收藏 / 最近观看的稳定标识（换线路不会丢收藏）。

## 卡片预览 / 收藏 / 最近观看

- **预览**：1.2 起**默认关闭**。开启后聚焦卡片 1.2 秒才起播，全局复用唯一一个 `PlayerView`（静音、360p、≤500 kbps）；移到别的卡片、进入全屏播放或离开 App 立即释放，连续失败 3 次自动彻底关闭。低性能盒子建议一直保持关闭
- **收藏**：墙面**长按 OK**，或遥控器上的收藏键（`KEYCODE_BOOKMARK`）；EPG 节目单里同样可用收藏键。收藏后卡片右上出现金色 ★，分组条出现「★ 收藏」
- **最近观看**：每次播放自动记录，最多 30 个，分组条出现「⏱ 最近观看」，按最近顺序排列

## 重新打包

**本工程可用命令行独立编译**（Gradle 8.7 / AGP 8.5.2 / Kotlin 1.9.24 / JDK 17 / SDK 34），不依赖 Android Studio。需自备 JDK 17 与 Android SDK 34（platforms/android-34、build-tools/34.0.0）。在项目根目录执行：

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
./gradlew --no-daemon assembleRelease
```

Windows PowerShell：把前两行换成 `$env:JAVA_HOME = "..."` / `$env:ANDROID_HOME = "..."`，再执行 `.\gradlew.bat --no-daemon assembleRelease`。

产物为 `app/build/outputs/apk/release/FlysnowTV.apk`。工程已附带 `gradlew` / `gradlew.bat` / `gradle-wrapper.jar`，Android Studio 打开也能直接 Sync；`settings.gradle` 配了阿里云 Maven 镜像优先 + 官方源兜底，`gradle.properties` 里 `android.builder.sdkDownload=false` 禁止 AGP 联网补 SDK（国内直连 Google 源会卡住）。

> release 签名需在 `keystore/` 下自备 `release.jks` 与 `keystore.properties`（字段名见 `app/build.gradle`），两者均不入库。自用侧载也可直接执行 `./gradlew assembleDebug`。

| 短按 MENU / SETTINGS | **呼出底部信息栏**并把焦点交给按钮行：`←→` 选按钮、`OK` 确认、`BACK` / `↑↓` 收起；再短按一次也收起 |

## 已知限制

- 只支持 HTTP(S) 的 HLS（m3u8）/ 渐进式视频；**不支持** udp/rtmp 组播、DRM 加密流
- 预览与全屏播放**不会同时解码**（1.2 单解码器策略）；单码率高清源无法「降码率」，只能按分辨率上限和带宽限制
- 应用不内置任何频道，全部频道来自你添加的订阅源；订阅地址失效时频道会播放失败，请更换或更新订阅
- 回看 / 时移完全取决于源：模板不支持时会尝试 `playseek=` 参数，多数源会直接报错，此时按快退键选「回到直播」即可；App 不做本地录制
- 预约提醒是**应用前台提醒**（盒子多无通知栏且后台受限），退出 App 后不会响；时间轴网格一次显示 8 个频道，更多频道用 ↑↓ 翻页
- XMLTV 频道匹配依赖 `tvg-id` / `display-name` 命名规范；命名完全不同的源可在 m3u 里补 `tvg-id`
- 调用外部播放器时无法传递自定义请求头，且不受 App 内画质设置约束
- 手机配置服务只在二维码页打开期间运行，且需要手机与盒子在同一局域网

## 盒子排障速查

| 现象 | 先做什么 |
| --- | --- |
| 启动卡在台标/图标界面 | 1.2 已移除每卡片 TextureView 并缩减首帧工作量；若仍卡，进设置关掉「卡片预览」和「后台续播」 |
| 画面出来但很卡 | 画质改 **720p / 省流**、保持加速引擎、优先用较稳定的 m3u8 直连源 |
| 起播要等很久 | 加速引擎 + HLS 免分片预加载已默认开启；检查源站 DNS / 首分片速度，或换一条线路（`← →`） |
| 某个频道播不了 | 自动切线路会依次尝试所有备用源；也可手动 `← →`；全失败时错误页会列出失败线路和原因 |
| 模拟器能播、盒子完全播不了 | 多为老盒子未启用 TLS1.2 或硬解不支持；已自动兼容。设置 → 播放诊断查看设备分级与 TLS，或改用更兼容的 m3u8 直连源 |
| 导入链接失败 | 看逐条失败原因；需要 Referer / UA 时在导入框填请求头，需要 POST / Token 时用「添加接口（URL）」高级表单 |
| 想看运行 / 崩溃日志 | 设置 → 播放诊断 → 生成日志文件 → `adb pull <显示的路径>`；或 `adb shell cat /data/data/com.iptv.tvplayer/files/diag.log` / `crash.log` |
| 回看报错 | 源不支持时移，按快退键选「回到直播」；需要源提供 `catchup-source` 或 `{utc}` 模板 |
